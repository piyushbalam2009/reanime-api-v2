Anime data.
One simple API.

A lightweight REST interface for searching ReAnime, retrieving anime details, and listing episodes. Explore requests interactively in the API playground.

Open API playground →

Getting started

Base URL

http://localhost:4000

When deployed, replace the local URL with your server's public origin. All API routes use the /api/v1 prefix. The API currently requires no API key.

Endpoints

GET /health

Checks whether the API process is responding. This endpoint does not verify that the upstream ReAnime website is healthy.

{
  "success": true,
  "data": { "status": "ok", "service": "reanime-api-v2" }
}
GET /api/v1/search?q={query}

Searches the source website and returns matching anime summaries.

  • q — required search text, 1–120 characters after trimming.
{
  "success": true,
  "data": [
    { "id": "anime-id", "title": "Anime title", "url": "https://…", "image": "https://…" }
  ]
}
GET /api/v1/anime/{id}

Fetches /anime/{id} from Re:ANIME and extracts the actual title, alternate title, synopsis, poster, genres, score, format, status, episode count, season and release year when the source page provides them.

  • id — required path parameter, 1–180 characters after trimming.
{
  "success": true,
  "data": {
    "id": "anime-id",
    "title": "Anime title",
    "url": "https://…",
    "description": "…",
    "image": "https://…",
    "genres": ["Action", "Adventure"]
  }
}

Optional fields are omitted when the scraper cannot find them.

GET /api/v1/anime/{id}/episodes

Fetches the Re:ANIME /watch/{id} page, where its episode list is rendered, and extracts episode numbers, titles and watch URLs. Results are sorted by episode number.

  • id — required path parameter, 1–180 characters after trimming.
{
  "success": true,
  "data": [
    { "id": "episode-id", "number": 1, "title": "Episode 1", "url": "https://…" }
  ]
}

Episode title and thumbnail are optional and are omitted when the source page does not expose them. This endpoint returns the source site's episode links; it does not claim that every episode has a playable server.

ReAnime streaming

GET /api/v1/anime/{id}/episodes/{episode}/servers?type=all

Fetches ReAnime's episode server links and returns the available sub/dub FlixCloud embed servers.

curl "http://localhost:4000/api/v1/anime/ANIME_ID/episodes/1/servers?type=sub"
GET /api/v1/stream/reanime/{sourceId}

Resolve a server's sourceId. This fetches the FlixCloud embed and runs its token/WASM decryption flow to obtain the HLS playlist, playlist key, subtitles, audio tracks, and quality variants when available.

curl "http://localhost:4000/api/v1/stream/reanime/SOURCE_ID"
GET /api/v1/proxy/hls?url={m3u8}&ref={referer}&pk={playlistKey}

Proxies HLS playlists and segments. Variant playlists, key/map URI attributes, and media segment links are rewritten through the API proxy. The proxy only accepts HTTPS URLs from the configured ReAnime/FlixCloud stream host allowlist.

GET /api/v1/proxy/subtitle?url={subtitleUrl}&ref={referer}

Proxies subtitle text with CORS headers for browser playback.

Start with an anime ID returned by search, obtain a server sourceId for an episode, then resolve that sourceId. Direct-playlist extraction depends on FlixCloud's current embed protocol and can fail if the provider changes its obfuscation or CDN hosts.

Response format

Successful response

{ "success": true, "data": … }

Error response

{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "Route not found"
  }
}

Invalid query or ID input returns HTTP 400. Unknown routes return HTTP 404. Upstream scraping failures return HTTP 502 with an UPSTREAM_ERROR code.

Examples

Search

curl "http://localhost:4000/api/v1/search?q=frieren"

Anime details

curl "http://localhost:4000/api/v1/anime/ANIME_ID"

Episodes

curl "http://localhost:4000/api/v1/anime/ANIME_ID/episodes"

Notes and limitations

  • Responses depend on the current public ReAnime website markup and availability.
  • Scraped fields may be absent when the source page does not expose them.
  • The API currently exposes search, anime details, and episode listing only. Streaming/server extraction is not part of the current REST surface.
  • Use reasonable request rates and follow the source website's terms and access restrictions.
